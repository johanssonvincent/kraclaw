FIX 1 — Server.Stop can hang forever (internal/server/server.go ~line 170).
GracefulStop() has no deadline; the passed ctx is only applied to the REST Shutdown. A stuck streaming RPC blocks shutdown indefinitely.
Fix: run grpcServer.GracefulStop() in a goroutine; wait for it with a timer (e.g. 10s, or derive from the passed ctx if it has a deadline); if it does not finish in time call grpcServer.Stop() (hard stop). Use the ctx's Done channel as well — if ctx fires, hard-stop.
Test first in server_test.go: a server with a streaming RPC that never returns must still shut down within the timeout (use a handler that blocks until ctx cancelled; assert Stop returns).

FIX 2 — CREDENTIAL_ENCRYPTION_KEY validation gap (internal/config/config.go ~line 143).
The key is only required when OpenAI is the SOLE platform credential. A multi-provider setup (Anthropic + OpenAI keys, plus per-group ChatGPT credentials in the CredentialStore) passes validation with no key, then fails at NewEncryptor startup.
Fix: require CREDENTIAL_ENCRYPTION_KEY whenever the CredentialStore/multi-provider path will be constructed. Look at how cmd/kraclaw decides to build NewEncryptor (grep NewEncryptor) and make Load/Validate consistent with that condition. Keep the error message style consistent with neighboring validation errors.
Test first in config_test.go: a config with both platform keys set but no encryption key must be rejected (or must trigger encryption setup) exactly when the multi-provider path requires it; and the existing single-provider cases must keep passing unchanged.

FIX 3 — Recurring-task executor failure deviates from documented semantics (internal/scheduler/scheduler.go ~165-203).
The documented contract (comments in the file and repo docs): an executor error on a RECURRING task triggers a compensating write NextRun = now + 1 minute and the task stays active for quick retry. The code instead leaves the pre-claimed NextRun (already advanced a full period).
Fix: on executor error for a recurring (schedule_type != once) task, write NextRun = now + 1 minute (compensating update) and record the error, per the documented semantics. Keep once-task behavior exactly as is (no retry). Be careful: the compensating write failure handling should follow the same transient/permanent classification used elsewhere in the file (read the surrounding error-handling code and match it).
Test first in scheduler_test.go using the existing mockTaskStore events pattern: a failing executor on an interval task must produce a compensating UpdateTask with NextRun ≈ now+1m and the task must remain active; a once-task must NOT get the compensating write.
