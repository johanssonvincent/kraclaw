FIX A — agent input payloads are unreadable (HIGH).
internal/server/api_services.go has two sites that send a bare JSON string as IPC input payload:
  - CreateSandbox (~line 630): payload, err := json.Marshal(req.Prompt)
  - PipeSandboxInput (~line 676): payload, err := json.Marshal(req.Text)
Agents' extractMessageText (cmd/kraclaw-agent-anthropic/main.go:158) unmarshals into struct{messages,text}, which always fails on a bare JSON string, so initial prompts/piped input are silently dropped.
Change both to json.Marshal(map[string]string{"text": ...}) — matching the shape orchestrator.go:761 already uses for {"messages": ...}.
Add a regression test: at minimum add a test in api_services_test.go asserting PipeSandboxInput publishes a payload that unmarshals into the agent-side struct {Messages,Text string} with Text == req.Text (existing tests use an embedded NATS server; follow the pattern of existing PipeSandboxInput tests if present).

FIX B — unbounded error-body read in credproxy (HIGH).
internal/credproxy/proxy.go, ModifyResponse (~line 413): io.ReadAll(resp.Body) on every >=400 response with no cap — a hostile upstream can OOM the proxy. Add a cap of 64 KiB: read through io.LimitReader; if the body is larger than the cap, log a warning and pass the ORIGINAL body through unchanged (do not replace it with a truncated body — truncation could corrupt SSE/JSON error handling). Only swap the body when it fits fully under the cap. Also resp.Header.Del("Content-Length") when you replace the body (resp.ContentLength alone is not enough — the header can disagree and break the client connection).
Write the test first in proxy_test.go: an upstream returning a huge (e.g. 1 MiB) error body must still proxy fine and arrive intact at the client; a small error body still gets swapped/logged as before.
